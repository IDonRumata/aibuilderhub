## 1. Что это за проект

Партнёрский обзорный сайт про AI-конструкторы приложений. Зарабатывает на
партнёрских ссылках. Контент двух видов: написанные вручную обзоры и
сравнения (основа дохода) и новостные посты, которые пишет конвейер (свежесть
домена и повод для рассылки).

| Параметр | Значение |
|---|---|
| Путь | `D:\Claude Code doc\Projects\Profitable website` |
| Репозиторий | `github.com/IDonRumata/aibuilderhub` (публичный) |
| Домен | aibuilderhub.app, DNS в Cloudflare, регистратор Namecheap |
| Стек сайта | Astro 7.3.2, статическая сборка, Tailwind 3 через PostCSS, Node 22 |
| Хостинг | Cloudflare **Worker** `aibuilderhub` со статикой (не Pages!), раздел 4 |
| Стек конвейера | Python 3.12, asyncio, pydantic v2, uv |
| Модель | `claude-sonnet-5` (переопределяется переменной `AIBH_MODEL`) |
| Эмбеддинги | Voyage API, при отсутствии ключа - локальный лексический фолбэк |
| Расписание | GitHub Actions, cron 06:30 и 15:30 UTC ежедневно |
| Темп | квота 3 поста в неделю (раздел 5) |
| Статей | 33: 23 вручную, 10 конвейером. На сайте 33 из 33 |

### Ограничения окружения

**Сборку сайта проверять только на Windows-машине владельца.** `node_modules`
установлены под Windows. В Linux-песочнице `npm i` запускать **нельзя** -
перезапишет нативные биндинги и сломает локальную разработку. На самой
Windows-машине `npm run build` и `npm audit fix` работают нормально.

**Интерпретатор конвейера:** `automation/.venv/Scripts/python.exe`. Не
`python3`. Системный `python` на машине есть, но без `pyyaml` и зависимостей.

**Ключей модели локально нет.** Файла `automation/.env` не существует. Боевые
прогоны идут только в GitHub Actions, где лежат секреты. Локально работает
всё, что не зовёт модель: `topics`, тесты, линтер.

**Wrangler локально не залогинен.** OAuth-токен в
`%APPDATA%\xdg.config\.wrangler\config\default.toml` протух в июле, refresh не
проходит. Для `wrangler deploy --dry-run` логин не нужен. Для настоящего
деплоя нужен, но он и не требуется: деплой делает Cloudflare сам.

## 3. Как работает сайт

Статический Astro. Контент - markdown в `src/content/blog/`, схема
фронтматтера в `src/content.config.ts`. Автор по умолчанию `Andrei Maroz`,
явно прописывать не нужно.

**Даты нигде не отображаются.** Осознанное решение: `pubDate` есть во
фронтматтере и нужен для сортировки, sitemap, RSS и разметки BlogPosting, но в
карточках и постах его нет. Вывод даты в интерфейсе - регрессия.

**Все ссылки на инструменты идут через `/go/<id>`.** Единственный источник
правды - `src/data/tools.json`. Скрипт `scripts/build-redirects.mjs` на этапе
`prebuild` генерирует `public/_redirects`: 302 на партнёрку или сайт
инструмента плюс 301 со старых `/tools/<id>` на обзоры. Чтобы подключить
партнёрку, достаточно вписать `affiliateUrl` в JSON: заработает во всех
ссылках сайта, включая старые статьи, без правки markdown.

**Карточка инструмента в конце поста** подбирается по тегам поста
(`PostLayout.astro` сопоставляет теги с `id` из tools.json). Нет совпадения -
ссылка на `/pricing`.

**Клики трекаются** в GA4 событием `affiliate_click` с названием инструмента и
страницей. Обработчик один, делегированный, в `BaseLayout.astro`.

**Безопасность.** `public/_headers`: CSP, HSTS, nosniff, frame-deny,
Referrer-Policy, Permissions-Policy. Worker со статикой применяет `_headers` и
`_redirects` так же, как Pages. Инлайновых обработчиков в шаблонах нет
намеренно, ховеры на CSS `:hover`, чтобы CSP не требовал `unsafe-hashes`.
История аудита в `SECURITY-AUDIT.md`.

**Рассылка.** Форма шлёт POST на отдельный Worker `aibuilderhub-subscribe`,
код в `workers/subscribe.js`. Он не часть деплоя сайта и деплоится отдельно.
Настройка в `SETUP-NEWSLETTER.md`, статус в разделе 11.

## 4. Как устроен деплой

Самый важный раздел. Шесть дней в сентябре конвейер работал, а читатель видел
404, и предыдущая версия этого документа причину угадала неверно.

### Три объекта в Cloudflare с похожими именами

| Имя | Тип | Что обслуживает |
|---|---|---|
| `aibuilderhub` | **Worker** | **aibuilderhub.app - живой сайт** |
| `aibuilderhub` | Pages | `aibuilderhub.pages.dev` - заброшенная июльская сборка, ни к чему не привязана |
| `aibuilderhub-subscribe` | Worker | эндпоинт подписки на рассылку |

Worker и Pages-проект с одинаковым именем - разные вещи. Любой деплой в
Pages-проект обновляет страницу, которую никто не читает.

### Как пост попадает к читателю

1. Конвейер коммитит пост в `main` из GitHub Actions.
2. Cloudflare Workers Builds видит пуш и собирает Worker `aibuilderhub`.
   Настройки сборки в панели: build command `npm run build`, deploy command
   `npx wrangler deploy`, ветка `main`, корень `/`.
3. `wrangler deploy` читает `wrangler.jsonc` из корня репозитория и заливает
   `dist/` как статические ассеты. Никакого серверного кода.
4. Через 1-2 минуты пост на сайте.

**Токен Cloudflare в GitHub не нужен и не заведён.** Деплой делает Cloudflare,
а не GitHub.

### Почему `wrangler.jsonc` нельзя удалять

До 9 сентября его в `main` не было. Не найдя конфигурации, `wrangler deploy`
сам решал, что это за проект: тянул `@astrojs/cloudflare` последней версии,
подключал как SSR-адаптер и пересобирал сайт через него. Адаптер разошёлся с
версией `astro` из `package-lock.json`, и каждый деплой с 3 сентября падал на
`MISSING_EXPORT renderForPrerender`. Команда сборки при этом проходила, поэтому
в GitHub всё было зелёное. Разбор в комментарии в начале `wrangler.jsonc` и в
`SETUP-DEPLOY.md`.

В репозитории есть ветка `origin/cloudflare/workers-autoconfig`, которую
27 июля создал бот Cloudflare. Она добавляет SSR-адаптер и `main:
dist/_worker.js`. **Не мержить.** Сайту SSR не нужен.

### Что делать, если сайт снова отстал

1. Сравнить число статей в репозитории и на сайте (раздел 0, пункт 3).
2. Панель Cloudflare -> Workers & Pages -> `aibuilderhub` (строка с доменом
   aibuilderhub.app) -> Deployments -> build history. Красная строка -
   упавший деплой. Настоящая ошибка в последних двадцати строках лога.
   Страница тяжёлая: через Chrome MCP надёжнее достать хвост лога через
   `javascript_tool`, чем скриншотами.
3. Там же кнопка **Retry build**. Токен не нужен.
4. Workflow **Deploy the site** в GitHub Actions - запасной рычаг на случай,
   когда сломана сама связка Cloudflare с репозиторием. Ему нужны секреты
   `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`. Их нет, и без них он
   отказывается запускаться.

### Bot Fight Mode выключен, и это важно

До 9 сентября в зоне был включён Bot Fight Mode. Он отдаёт managed challenge
(HTTP 403) на любой запрос с адреса дата-центра: страницы, статику, XML.
Браузерный User-Agent не помогает, Cloudflare смотрит на TLS-отпечаток.
Проверено тремя способами. Из-за этого проверки деплоя из GitHub Actions не
работали вовсе, а RSS-читалки и превью-боты соцсетей получали отказ. Google и
Bing в белом списке, индексация не страдала.

Выключен с разрешения владельца: Security -> Settings -> bot traffic. **Если
его когда-нибудь включат обратно, в тот же день нужно добавить правило Skip в
Security -> WAF для запросов проверок**, иначе сторож ослепнет. Проверки
распознают 403 и пишут в лог "проверка не выполнилась", а не ложную тревогу.

## 5. Как работает контент-конвейер

Код в `automation/`. Документация модуля - `automation/BRIEF.md`. Исходное ТЗ
- `TZ-CONTENT-AUTOMATION.md`.

### Поток данных

```
cadence       сколько постов должно выйти сегодня? ноль - выходим сразу,
   |          не тронув ни фиды, ни модель (стоимость прогона = 0)
ingest        25 источников (RSS + HN API + Reddit), окно 96 часов,
   |          упавший источник логируется и пропускается
scoring       кластеризация в темы и ранжирование, четыре гейта
   |
dedup         URL, эмбеддинги, 3-граммы заголовков, коллизия slug,
   |          карантин проваленных тем (7 дней)
writer        черновик 500-1000 слов по voice.md и 2-4 источникам
   |
critics       4 критика до 3 раундов: fact-checker, ai-pattern, editor,
   |          seo-integrity; каждый возвращает строгий JSON
humanizer     регекс-скан стилевых правил + переписывание проблемных мест
   |
publisher     .md в src/content/blog; тема провалилась - в карантин,
   |          берётся следующая, пока не выполнена квота или 5 попыток
workflow      smoke-сборка, стилевой гейт, commit, push в main,
   |          ожидание поста в живой карте сайта
Cloudflare    Workers Builds собирает и деплоит по пушу (раздел 4)
```

Типичная воронка, замер 9 сентября: 453 сырых записи, 181 кандидат, 16
годных тем. Для трёх постов в неделю запас больше чем пятикратный.

### Квота вместо календаря (`services/cadence.py`)

Cron срабатывает каждый день дважды, решение принимает квота. Прогон считает
посты конвейера за последние 7 суток. Ручные обзоры в квоту не входят.

| Ситуация | Что делает прогон |
|---|---|
| 3 поста за 7 суток уже есть | выходит сразу, до фидов, стоимость 0 |
| последний пост моложе 36 ч | пропускает, чтобы неделя не схлопнулась в один день |
| отстаём от квоты | пишет один пост |
| тишина дольше 72 ч и долг от двух | пишет до двух постов |

Пороги в `settings.py`: `weekly_target_posts`, `min_hours_between_posts`,
`catchup_after_hours`, `max_posts_per_run`. Ручной прогон обходит квоту флагом
`force`.

Большинство прогонов - холостые, в истории коммитов это `chore(state): record
skipped run`. Это нормально и ничего не стоит.

**GitHub сильно задерживает cron.** Утренний запуск 06:30 UTC фактически
стартует около 11:00-13:00 UTC, дневной 15:30 - около 17:30-20:00. Иногда не
стартует вовсе. Именно поэтому cron ежедневный и продублирован.

### Провал темы не стоит дня

Тема, не прошедшая критиков, хьюманайзер или финальный дедуп, пишется в
`failed_topics.json` на 7 дней, и прогон берёт следующую - до пяти попыток
(`max_topic_attempts_per_run`). Настоящий ограничитель - не счётчик, а
бюджет: перед каждой попыткой прогон проверяет остаток месяца и свой потолок
вызовов и останавливается по любому из них. Плохой день не может съесть месяц.

Потолок вызовов на прогон (`max_llm_calls_per_run`, 130) обязан быть не
меньше произведения попыток на вызовы на пост (5 на 25), иначе счётчик
попыток декоративный. Это держит тест
`test_the_run_can_afford_every_attempt_it_is_allowed`.

### Четыре гейта отбора тем (`services/scoring.py`)

Главное место, где конвейер решает не публиковать. Каждый гейт появился после
конкретного отказа в проде.

1. **Самореклама.** Посты от первого лица ("I built X") выбрасываются до
   кластеризации. Привязка к местоимению рядом с глаголом создания, поэтому
   "Anthropic launched X" проходит.
2. **Ниша.** `min_niche_score` по словарю в `sources.yaml`. Режет около 70%
   кандидатов.
3. **Цитируемый источник.** Нужно издание, HN или Reddit-тред с видимой
   вовлечённостью. Иначе fact-checker не сможет ничего сверить.
4. **Объём материала.** Меньше 400 символов исходника - в отказ. 700 слов из
   блурба на 166 символов - гарантированная выдумка.

### Потолки расходов (`services/budget.py`)

| Уровень | Лимит | Что останавливает |
|---|---|---|
| Вызовы на один пост | 25 | зациклившегося критика; пост бросается, прогон живёт |
| Вызовы за прогон | 130 | всё остальное внутри запуска |
| Токены за прогон | 900k вход / 180k выход | утечку внутри запуска |
| **Оценка трат за месяц** | **12 долларов** | накопление между запусками |

Месячный счётчик в `automation/state/usage.json`, проверяется **до первого
вызова модели**. Упёрлись - конвейер не стартует до следующего месяца, и это
выглядит как тишина.

Замер: одна попытка стоит около 0.38-0.45 доллара, вышел пост или нет. Около
40% попыток критики отклоняют. Три поста в неделю - около 9-10 долларов в
месяц. Если счёт важнее темпа, менять одно число - `weekly_target_posts`: два
поста в неделю стоят около 6.

Перед серией ручных прогонов смотреть остаток в `usage.json`. Сессия
отладки из пяти запусков стоит около полутора долларов.

### Состояние между прогонами (`automation/state/`)

| Файл | Назначение |
|---|---|
| `published_topics.json` | реестр тем конвейера: URL, заголовок, slug, хэш, дата |
| `embeddings.json` | векторы опубликованных постов для смыслового dedup |
| `failed_topics.json` | карантин проваленных тем на 7 дней, заодно история отказов |
| `usage.json` | расход по месяцам |
| `last_run.json` | итог последнего прогона |

Состояние коммитит сам конвейер, поэтому удалённая ветка всегда впереди
локальной. Перед любым пушем: `git pull --rebase origin main`.

## 6. Наблюдаемость

### Проверка после публикации

Шаг `Wait for the live site to serve the new post` в `content-pipeline.yml`
после пуша ждёт, пока slug нового поста появится в
`https://aibuilderhub.app/sitemap-0.xml`. Карта сайта, а не сама страница,
потому что Astro пересобирает её из контента на каждой сборке: slug в
отданной карте доказывает, что живая сборка содержит пост. До 20 попыток по
20 секунд, потом предупреждение в сводке прогона. На 403 останавливается
сразу и пишет, что проверка не выполнилась.

### Сторож молчания

`.github/workflows/content-watchdog.yml`, каждый день в 17:30 UTC. Модель не
зовёт, стоит ноль. Задаёт два вопроса.

1. **Давно ли публиковали?** Свежайшая отметка в `published_topics.json`.
   Больше 96 часов - issue с меткой `pipeline-stall`.
2. **Ту ли сборку отдаёт сайт?** Свежайший недраф из `src/content/blog/`
   ищется в живой `sitemap-0.xml`. Нет - issue с меткой `site-stale`.

Issue приходят владельцу письмом и закрываются сами, когда всё выправилось.
Для теста тревоги у ручного запуска есть параметр `stall_hours`.

Второй вопрос добавлен после сентябрьского простоя: запись в реестре -
обещание, что пост существует, а не доказательство, что его можно прочитать.

## 7. Команды

Из папки `automation/`:

```bash
# отбор тем: без модели и без записи, видно всю воронку
.venv/Scripts/python.exe -m aibh_pipeline.main topics --limit 12

# полный прогон с выводом поста, ничего не пишет и не коммитит (нужен ключ модели)
.venv/Scripts/python.exe -m aibh_pipeline.main run --dry-run

# тесты и линтер
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check .
```

Из корня проекта:

```bash
# сборка сайта и проверка конфигурации деплоя без реального деплоя
npm run build
npx --yes wrangler@4 deploy --dry-run

# боевой прогон по квоте (в выполненную неделю ничего не сделает)
gh workflow run content-pipeline.yml -f draft=false -f dry_run=false

# опубликовать сейчас, невзирая на квоту
gh workflow run content-pipeline.yml -f force=true

# сторож вручную
gh workflow run content-watchdog.yml
```

Разбор прогона, логи структурные, JSON построчно:

```bash
JOB=$(gh run view <RUN_ID> --json jobs -q '.jobs[0].databaseId')
gh api "repos/IDonRumata/aibuilderhub/actions/jobs/$JOB/logs" \
  | grep -E '"event": "(cadence|scoring_complete|topic_selected|critique_round|topic_failed|day_skipped|usage)"'
```

## 8. Типовые отказы и как их читать

**Главная закономерность проекта: почти все отказы - не "плохой текст", а
взаимно неудовлетворимые правила или сигналы, которые врут о здоровье.** При
новом отказе сначала проверить, физически ли выполнимо требование и тот ли
объект мы измеряем, и только потом чинить писателя.

| Симптом | Причина | Как решено |
|---|---|---|
| Пост в `main`, CI зелёный, на сайте 404 | Деплой падает на стороне Cloudflare, GitHub этого не видит | `wrangler.jsonc` со статикой; проверка карты сайта после публикации; второй вопрос сторожа |
| Деплой падает на `MISSING_EXPORT renderForPrerender` | Без конфигурации wrangler сам подключает SSR-адаптер последней версии | `wrangler.jsonc`, раздел 4 |
| Проверка из Actions получает 403 | Bot Fight Mode, смотрит на TLS-отпечаток | Выключен; проверки распознают 403 |
| `day_skipped: critics returned REJECT`, но `blocking: 0` во всех раундах | SEO-критик требует внутренние ссылки, fact-checker их вычёркивает | Fact-checker получает каталог статей и знает, что это навигация |
| `banned patterns survived the rewrite: too-vague` | Правило требует цифр, хьюманайзеру запрещено их добавлять | Правило в `ADVISORY_RULES`: логируется, не блокирует |
| `banned patterns: word:<чужое имя>` | Стилевое правило сработало на имя пакета в коде или URL | Правила идут по маске `mask_non_prose` |
| Критики просят убрать "лишний бэктик" | Незакрытый блок кода | `drop_orphan_code_fence` до ревью |
| Пост написан, упал шаг "Style gate" | CI-гейт и конвейер по-разному считали блокирующие правила | Оба уважают `ADVISORY_RULES` |
| `model: String should have at least 1 character` | Actions подставляет пустую строку вместо незаданной переменной | Валидаторы трактуют пустую строку как "не задано" |
| В отборе побеждают "I built X" | Reddit JSON даёт 403, RSS без голосов | `engagement_measured` + фильтр саморекламы |
| fact-checker валит выдуманные цифры | `voice.md` требовал конкретики любой ценой | Конкретика только по источнику; пост без цифр лучше выдуманных |
| Тишина несколько дней | Одна тема на прогон, два слота в неделю | Квота, ежедневный cron, до пяти попыток |
| CI красный после пуша без изменения зависимостей | Вышли новые advisory на дерево пакетов | `npm audit fix` на Windows-машине, затем сборка и `wrangler deploy --dry-run` |

### Грабли инструментов

**Не писать регулярки с `\b` через shell-heredoc в Python.** При записи файла
через `python - <<'PY'` экранирование обрабатывается дважды, и `\\b`
превращается в байт `\x08`. Регулярка молча перестаёт работать. Проверка:
`python -c "print(repr(module.SOME_RE.pattern))"`. Для правок с обратными
слэшами использовать инструмент редактирования файла.

**Большой heredoc через Bash с русским текстом может не распарситься.** Для
записи длинных документов использовать инструмент записи файла.

**Пуш почти всегда отбивается с первого раза.** Рабочая последовательность:
`git pull --rebase origin main && git push origin main`.

**Панель Cloudflare тяжёлая.** Скриншоты через Chrome MCP часто падают по
таймауту. Надёжнее `find` + `ref` и `javascript_tool` для чтения текста.

**Выход шага workflow передавать через `env:`**, а не вставлять `${{ }}` прямо
в `run:`. Так уже сделано везде, держать этот стиль.

## 12. Стратегическое

**Воронка узкая по устройству, но её хватает.** Фильтр ниши режет около 70%
кандидатов, и запас всё равно пятикратный. Расширять источники ради объёма не
нужно. Если понадобится - крутить `min_niche_score` или `sources.yaml`, но
**не** ослаблять контроль качества: он единственное, что отделяет сайт от
scaled content abuse.

**Три поста в неделю - осознанный потолок.** Поднять `weekly_target_posts`
можно одной строкой, но ежедневная лента машинных новостей - ровно та форма,
по которой бьёт политика Google, а органику держит не объём, а ссылки
(`LINK-BUILDING-PLAN.md`). Сейчас 23 ручных обзора против 10 сгенерированных.
Паритет наступит примерно к середине октября. Там стоит остановиться и
посмотреть Search Console, прежде чем добавлять темп.

**SEO.** Снимок Search Console за 3 месяца на 17 августа: 41 страница в
индексе, 445 показов, 1 клик, средняя позиция 38.8. Проблема не в индексации
и не в сниппетах: CTR 0.2% - норма для четвёртой страницы выдачи. Нужны
авторитет домена и ссылки, а не новые статьи. План в `LINK-BUILDING-PLAN.md`.
Свежий снимок Search Console после сентябрьского ремонта ещё не снимался.

## 13. Как работать с владельцем

Разговор **только на русском**. Длинное тире не использовать, только дефис.
Пути к файлам писать полностью, от буквы диска.

**Не поддакивать.** Андрей прямо просил жёсткую критику и поиск слабых мест.
Если предложенное им решение хуже альтернативы - сказать с цифрами. Присланные
ссылки и данные сначала проверять, потом использовать.

**Он нетехнический.** Инструкции пошагово, с точными путями в интерфейсе.
Надёжнее открыть страницу браузером и посмотреть самому, чем описывать кнопку
по памяти.

**Секреты в поля не вводить ни при каких условиях**, даже когда он прямо
просит и присылает ключи в чат. API-ключи, банковские реквизиты, налоговые
формы он вводит сам. Границу объяснять спокойно и сразу говорить, что именно
нажать.

**Полный доступ на продуктовую работу дан:** коммитить, пушить, перезапускать
конвейер, чинить деплой можно без запроса. Спрашивать на развилках по сути
(что публиковать, какую стратегию выбрать) и перед изменением настроек
аккаунтов: DNS, безопасность зоны, удаление проектов в Cloudflare.

**Chrome MCP** видит его залогиненные сессии, включая Cloudflare. Расширение
иногда отваливается - проверять `list_connected_browsers`.
