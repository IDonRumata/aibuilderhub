## 1. Что это за проект

Партнёрский обзорный сайт про AI-конструкторы приложений. Зарабатывает на
партнёрских ссылках. Контент двух видов: написанные вручную обзоры и
сравнения (основа дохода) и автогенерируемые новостные посты (свежесть
домена и повод для рассылки).

| Параметр | Значение |
|---|---|
| Путь | `D:\Claude Code doc\Projects\Profitable website` |
| Стек сайта | Astro 7.2.0, статическая сборка, Tailwind 3 через PostCSS |
| Стек конвейера | Python 3.12, asyncio, pydantic v2, uv |
| Хостинг | Cloudflare Pages, автодеплой при пуше в `main` |
| Репозиторий | `github.com/IDonRumata/aibuilderhub` (публичный) |
| Домен | aibuilderhub.app, DNS в Cloudflare, регистратор Namecheap |
| Статей | 28 (23 написаны вручную, 5 сгенерированы конвейером) |
| Расписание | GitHub Actions, cron пн и чт 06:30 UTC |

### Ограничения окружения, важные с первой минуты

**Песочница Linux не может собрать сайт.** `node_modules` установлены под
Windows, нативные биндинги под Linux не работают. `npm i` в песочнице
запускать **нельзя** - перезапишет Windows-биндинги и сломает локальную
разработку. Проверять сборку только через `npm run build` на машине
владельца.

**Песочница режет внешние домены по allowlist.** `db.don-rumata.ru`
недоступен.

**Локальный интерпретатор конвейера:** `automation/.venv/Scripts/python.exe`
(Windows-пути, не `python3`).

## 2. Как работает сайт

Статический Astro. Контент - markdown в `src/content/blog/`, схема
фронтматтера в `src/content.config.ts`.

**Даты нигде не отображаются.** Это осознанное решение: `pubDate` есть в
фронтматтере и нужен для сортировки, sitemap, RSS и разметки BlogPosting, но
в интерфейсе его нет ни в карточках, ни в постах. Если увидите вывод даты в
UI - это регрессия.

**Все ссылки на инструменты идут через `/go/<id>`.** Единственный источник
правды - `src/data/tools.json`. Скрипт `scripts/build-redirects.mjs` на этапе
`prebuild` генерирует из него `public/_redirects` с 302-редиректами (плюс
301-редиректы со старых URL `/tools/<id>` на обзоры). Чтобы подключить
партнёрку, достаточно вписать `affiliateUrl` в JSON: заработает сразу во всех
ссылках сайта, включая уже опубликованные статьи, без правки markdown.

**Карточка инструмента в конце каждого поста** подбирается автоматически по
тегам поста (`PostLayout.astro` сопоставляет теги с `id` из tools.json).
Посты без совпадения получают ссылку на `/pricing`.

**Клики трекаются** в GA4 событием `affiliate_click` с названием инструмента
и страницей. Обработчик один, делегированный, в `BaseLayout.astro`.

**Безопасность.** `public/_headers` содержит CSP, HSTS, nosniff, frame-deny,
Referrer-Policy, Permissions-Policy. Инлайновых обработчиков событий в
шаблонах нет намеренно - ховеры сделаны на CSS `:hover`, чтобы CSP не
требовал `unsafe-hashes`. Подробности и история аудита в `SECURITY-AUDIT.md`.

`npm audit` чист (0 уязвимостей). Сайт мигрирован с Astro 4 на 7 именно
ради этого - иначе не закрывались 6 high.

## 3. Как работает контент-конвейер

Код в `automation/`. Своя документация модуля - `automation/BRIEF.md`.

### Поток данных

```
ingest        собрать кандидатов из 25 источников (RSS + HN API + Reddit)
   |          окно 96 часов, параллельно, упавший источник логируется и пропускается
scoring       кластеризовать в темы и отранжировать; ЧЕТЫРЕ ГЕЙТА (см. ниже)
   |
dedup         выбросить уже освещённое: URL, эмбеддинги, 3-граммы заголовков,
   |          коллизия slug, карантин ранее провалившихся тем (7 дней)
writer        черновик 500-1000 слов по voice.md и 2-4 источникам
   |
critics       4 критика в цикле до 3 раундов (fact-checker, ai-pattern,
   |          editor, seo-integrity), каждый возвращает строгий JSON
humanizer     регекс-скан стилевых правил + переписывание проблемных мест
   |
publisher     .md в src/content/blog, git commit, push в main
   |
Cloudflare    автодеплой по пушу
```

### Четыре гейта отбора тем (`services/scoring.py`)

Это главное место, где конвейер решает не публиковать. Каждый гейт добавлен
после конкретного отказа в проде:

1. **Самореклама.** Посты от первого лица («I built X», «my first app»)
   выбрасываются до кластеризации. Привязка к местоимению рядом с глаголом
   создания, поэтому «Anthropic launched X» проходит.
2. **Ниша.** `min_niche_score` по словарю в `sources.yaml`. Самый мощный
   фильтр: режет примерно 70% кандидатов.
3. **Цитируемый источник.** Тема обязана иметь издание, публикацию на HN
   или Reddit-тред с **видимой** вовлечённостью. Одинокий Reddit-пост с
   неизвестным рейтингом не годится: fact-checker потом не сможет ничего
   сверить.
4. **Объём материала.** Меньше 400 символов исходника - отбрасывается.
   700 слов из 166 символов блурба - это гарантированная выдумка.

Типичная воронка: ~450 сырых записей → ~180 свежих и уникальных → ~13 тем.

### Три потолка расходов (`services/budget.py`)

| Уровень | Лимит | Что останавливает |
|---|---|---|
| Вызовы за прогон | 25 | зациклившегося критика |
| Токены за прогон | 400k вход / 80k выход | утечку внутри запуска |
| **Оценка трат за месяц** | **$5** | всё остальное, включая ручные прогоны |

Месячный счётчик в `automation/state/usage.json`, проверяется **до первого
вызова модели**. Упёрлись - конвейер отказывается стартовать до следующего
месяца.

**Это реальный операционный риск, а не формальность.** Один прогон стоит
примерно $0.39. Два плановых в неделю дают около $3.5 в месяц. В августе
израсходовано $4.20 из $5, и туда попали отладочные прогоны. Сессия отладки
из пяти запусков стоит около $1.5 и может незаметно выбить месяц за потолок,
после чего публикации просто прекратятся. Перед серией ручных прогонов
смотреть остаток в `usage.json`.

### Состояние между прогонами (`automation/state/`)

| Файл | Назначение |
|---|---|
| `published_topics.json` | реестр тем: URL, канонический заголовок, slug, хэш |
| `embeddings.json` | векторы опубликованных постов для смыслового dedup |
| `failed_topics.json` | карантин провалившихся тем на 7 дней |
| `usage.json` | накопленный расход по месяцам |
| `last_run.json` | итог последнего прогона (что опубликовано, сколько вызовов) |

Состояние коммитится самим конвейером из GitHub Actions. Из-за этого
**удалённая ветка регулярно уходит вперёд локальной**.

## 5. Эксплуатация: команды и диагностика

Всё из папки `automation/`, интерпретатор `.venv/Scripts/python.exe`.

```bash
# только отбор тем: без вызовов модели, без записи, видно всю воронку
.venv/Scripts/python.exe -m aibh_pipeline.main topics --limit 12

# полный прогон: печатает пост, ничего не пишет и не коммитит
.venv/Scripts/python.exe -m aibh_pipeline.main run --dry-run

# тесты и линтер
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check .
```

Ручной запуск боевого прогона:

```bash
gh workflow run content-pipeline.yml -f draft=false -f dry_run=false
```

Разбор прогона (логи структурные, JSON построчно):

```bash
JOB=$(gh run view <RUN_ID> --json jobs -q '.jobs[0].databaseId')
gh api "repos/IDonRumata/aibuilderhub/actions/jobs/$JOB/logs" \
  | grep -E '"event": "(scoring_complete|topic_selected|critique_round|day_skipped|humanizer_unresolved|usage)"'
```

Ключевые события в логах: `scoring_complete` (вся воронка с разбивкой по
гейтам), `topic_selected`, `critique_round` (вердикт и число блокирующих
замечаний), `humanizer_advisory` против `humanizer_unresolved`,
`day_skipped` с причиной, `usage` с расходом.

### Расписание работает, но время плавает

Cron стоит на 06:30 UTC, фактические запуски наблюдались в 11:29 и 14:15.
GitHub задерживает плановые задачи под нагрузкой, иногда на часы, иногда
пропускает. **Отсутствие прогона в ожидаемое время само по себе не поломка.**
На 7 сентября 11:51 UTC понедельничный запуск ещё не отработал при cron на
06:30. Прежде чем чинить - проверить, не в задержке ли дело, и при
необходимости запустить вручную.

## 6. Типовые отказы и как их читать

**Главная закономерность проекта: почти все отказы - это не «плохой текст», а
взаимно неудовлетворимые правила. Одно требует того, что другое запрещает.**
При новом отказе первым делом проверять, физически ли выполнимо требование, и
только потом чинить писателя. Пять из семи найденных багов были именно
такими.

| Симптом в логах | Причина | Как решено |
|---|---|---|
| `day_skipped: critics returned REJECT`, но `blocking: 0` во всех раундах | SEO-критик требует внутренние ссылки, fact-checker вычёркивает их как бездоказательные | Fact-checker получает каталог опубликованных статей и знает, что это навигация, а не утверждения |
| `banned patterns survived the rewrite: too-vague` | Правило требует 3 цифры, humanizer'у **намеренно** запрещено их добавлять (идёт после fact-checker, выдумка ушла бы непроверенной) | Правило переведено в `ADVISORY_RULES`: сканируется, логируется, не блокирует |
| `banned patterns: word:<чужое имя>` | Стилевое правило сработало на название чужого пакета внутри кода или URL | Правила слов и фраз идут по маске `mask_non_prose`, где код и адреса затёрты с сохранением позиций |
| Три критика подряд просят убрать «лишний бэктик» | Модель открыла блок кода и не закрыла; «убери лишний» не говорит какой именно | `drop_orphan_code_fence` убирает непарный маркер до ревью, парные блоки не трогает |
| Пост написан, сайт собрался, упал шаг «Style gate» | CI-гейт считал фатальным правило, которое конвейер уже пропускал | Оба гейта уважают `ADVISORY_RULES`, определение блокирующего одно |
| `model: String should have at least 1 character` | GitHub Actions подставляет **пустую строку** вместо незаданной переменной | Валидаторы в `settings.py` трактуют пустую строку как «не задано» |
| В отборе побеждают посты «I built X» | Reddit блокирует JSON (403), RSS-фолбэк не несёт голосов, `min_upvotes` не с чем сравнивать | `engagement_measured` отличает «голосов ноль» от «данных нет» + фильтр саморекламы |
| fact-checker валит выдуманные цифры | `voice.md` требовал конкретики с примерами из обзоров, где автор сам замерял | В раздел про новости добавлено: конкретика значит конкретику **по источнику**, пост без цифр лучше поста с выдуманными |

### Грабли инструментов, стоившие времени

**Не писать регулярки с `\b` через shell-heredoc.** При записи файла через
`python - <<'PY'` внутри `Bash` экранирование обрабатывается дважды, и `\\b`
превращается в **реальный байт `\x08`** внутри строки. Регулярка молча
перестаёт работать, `grep` и терминал этот байт не показывают. Проверка:
`python -c "print(repr(module.SOME_RE.pattern))"`. Для правок с обратными
слэшами использовать инструмент редактирования файла, а не heredoc.

**Пуш почти всегда отбивается с первого раза.** Конвейер коммитит состояние
из Actions, удалённая ветка уходит вперёд. Рабочая последовательность:
`git pull --rebase origin main && git push origin main`.

## 7. Открытые задачи

### Подтверждено сломано

**`www.aibuilderhub.app` отдаёт 525** (SSL handshake failed). В DNS запись
`www CNAME parkingpage.namecheap.com` (Proxied) - остаток от регистратора.
Нужно заменить на CNAME к `aibuilderhub.pages.dev` либо удалить и добавить
домен в Cloudflare Pages как alias. Часть аудитории, набирающая адрес с
`www`, видит ошибку. Проверено 7 сентября, всё ещё воспроизводится.

### Мелочи

**4 статьи с устаревшим авторством.** В `content.config.ts` дефолт уже
`Andrei Maroz`, но в этих файлах он прописан явно как `AIBuilderHub`:
`bubble-review-2026.md`, `lovable-review-2026.md`, `v0-review-2026.md`,
`webflow-review-2026.md`. Достаточно удалить строку `author:`.

**Битый `sitemap.xml` в Search Console** со статусом «Не получено» с 8 июля.
Такого файла нет, Astro генерирует `sitemap-index.xml`. Удалить старый.

### Требует действий владельца

**Reddit как источник почти мёртв.** JSON отдаёт 403, RSS - 429. Прогон не
ломает, источник деградирует мягко, но пользы не приносит. Чтобы вернуть,
нужен OAuth-доступ к Reddit API, то есть регистрация приложения на их
стороне.

**Статус рассылки не перепроверялся.** Страница `/newsletter/confirmed/`
отдаёт 200, значит фронт на месте. Задеплоен ли воркер с DOI-шаблоном и
вписаны ли переменные в Cloudflare - неизвестно: проверка требует POST на
живой эндпоинт, а это создаёт реальный контакт в базе. Детали в
`SETUP-NEWSLETTER.md`.

**Токен NocoDB засвечен** - владелец присылал его в чат открытым текстом.
Ротация не подтверждена. Также почистить историю PowerShell:
`Remove-Item (Get-PSReadlineOption).HistorySavePath`

### Стратегическое

**Воронка узкая по устройству.** Фильтр релевантности ниши режет около 70%
кандидатов. В тихий день конвейер честно пропустит публикацию. Если нужно
больше постов - крутить `min_niche_score` или расширять `sources.yaml`, но
**не** ослаблять контроль качества: он сейчас единственное, что отделяет
сайт от того самого scaled content abuse, за который Google наказывает.

**SEO.** Данные Search Console за 3 месяца (снимок 17 августа): 41 страница
в индексе, 445 показов, **1 клик**, средняя позиция **38,8**. Проблема не в
индексации и не в сниппетах - CTR 0,2% это норма для четвёртой страницы
выдачи. Нужен авторитет домена и ссылки, а не новые статьи. План в
`LINK-BUILDING-PLAN.md`. Отсюда и решение публиковать два раза в неделю, а
не ежедневно.

## 10. Как работать с владельцем

Разговор **только на русском**. Длинное тире не использовать, только дефис.

**Не поддакивать.** Андрей прямо просил жёсткую критику и поиск слабых мест.
Если предложенное им решение хуже альтернативы - сказать об этом с цифрами.
Если он присылает ссылку или данные, сначала проверить, а потом использовать:
дважды присланные «партнёрские» ссылки оказывались не теми, чем казались.

**Он нетехнический.** Инструкции пошагово, с точными путями в интерфейсе.
Несколько раз выяснялось, что он не находит кнопку, описанную словами:
надёжнее открыть страницу браузером и посмотреть самому, чем описывать по
памяти.

**Секреты в поля не вводить ни при каких условиях**, даже когда он прямо
просит («сделай сама») и присылает ключи в чат. Это касается API-ключей,
банковских реквизитов, налоговых форм. Границу объяснять спокойно и сразу
предлагать, что именно он должен нажать сам.

**Полный доступ на продуктовую работу дан:** коммитить, пушить, деплоить,
перезапускать конвейер можно без запроса разрешения. Спрашивать только на
развилках по сути: что публиковать, какую стратегию выбрать.

Chrome MCP видит его залогиненные сессии, но расширение иногда отваливается -
проверять `list_connected_browsers`. Тяжёлые страницы (Brevo, impact.com)
подвисают: надёжнее `find` + `ref`, чем клики по координатам.
