# ТЗ: Автономный контент-конвейер для AIBuilderHub

Версия: 1.0. Исполнитель: Claude Code. Заказчик: Andrea.
Проект: `D:\Claude Code doc\Projects\Profitable website` (Astro 4 + Tailwind + Cloudflare Pages, домен aibuilderhub.app).

---

## 1. Цель

Полностью автоматический ежедневный цикл: сбор горячих AI-новостей из внешних источников -> отбор самой виральной темы -> написание поста человеческим языком -> многоуровневая проверка агентами-критиками -> дедупликация -> автопубликация на сайт. Участие владельца: читать уже опубликованные посты и при желании править. Никаких ручных шагов в ежедневном цикле.

Не-цели (в этой версии): мультиязычность, генерация картинок, кросспостинг в соцсети, комментарии.

## 2. Утвержденные решения

- Оркестрация: **GitHub Actions**, cron ежедневно в 06:30 UTC (08:30 Warsaw).
- Режим: **полный автопаблиш**, правки постфактум. Плюс ручной запуск через `workflow_dispatch`.
- Источники: **RSS техмедиа + Hacker News API + Reddit JSON API** (без скрейпинга HTML сайтов - только официальные фиды и API).
- Язык постов: **английский**.
- Даты в публикациях **не отображаются** ни в карточках, ни в самих постах (см. п. 7.2).
- LLM: Anthropic API (модель по умолчанию `claude-sonnet-4-5`, вынести в конфиг).

## 3. Архитектура

Монорепо, новая папка `automation/` внутри существующего проекта. Python 3.12, asyncio, строгая типизация.

```

│                             # pydantic-settings, tenacity, structlog, python-slugify

│   └── style/
│       ├── voice.md          # голос сайта (выжимка из существующих постов)
│       └── banned_patterns.yaml  # стоп-слова и анти-AI паттерны (п. 6)
├── src/aibh_pipeline/
│   ├── settings.py           # pydantic-settings, все ключи только из env
│   ├── models.py             # Pydantic-модели: SourceItem, ScoredTopic,
│   │                         # DraftPost, CritiqueReport, PublishResult
│   ├── clients/

│   │   ├── rss.py                # feedparser поверх httpx
│   │   ├── hackernews.py         # Firebase API HN

│   │   │                     # пересечение темы в 2+ источниках, свежесть

│   │   ├── critics.py        # мультиагентный контроль качества (п. 4)
│   │   ├── humanizer.py      # финальная зачистка AI-паттернов (п. 6)
│   │   └── publisher.py      # запись .md в src/content/blog, git commit
│   └── main.py               # оркестратор: единая точка входа, exit codes
├── state/
```

### 3.1 Ежедневный поток (main.py)

1. **Ingest**: собрать 50-150 кандидатов из sources.yaml. Каждый -> `SourceItem` (title, url, source, published_at, score_raw, summary). Любой упавший источник логируется и пропускается - пайплайн не падает целиком.
2. **Scoring**: нормализовать сигналы, отобрать топ-5 тем. Бонус за релевантность нише (AI-инструменты, вайб-кодинг, no-code, соло-предприниматели), штраф за темы вне ниши (политика, крипта, железо).
3. **Dedup-фильтр** (п. 5): выкинуть темы, уже освещенные на сайте. Взять лучшую оставшуюся. Если все 5 - дубли, взять следующую пятерку; если кандидатов нет вообще - завершиться с notice, день пропускается (лучше пропуск, чем мусор).
4. **Research**: writer-агент получает title + url + summary источников по теме (2-4 источника). Текст статей-первоисточников НЕ копируется - только факты, переработанные своими словами, с 1-2 ссылками на первоисточники в теле поста.
5. **Write**: черновик 600-1000 слов по voice.md.
6. **Critics loop** (п. 4): до 3 итераций правок.
7. **Humanize** (п. 6): регекс-проверка + LLM-переписывание проблемных мест.
8. **Publish**: валидный frontmatter -> `src/content/blog/<slug>.md` -> git commit + push в main -> деплой срабатывает сам (п. 8). Обновить state-файлы в том же коммите.
9. **Notify**: итог в GitHub Actions summary. Опционально (фаза 2) - сообщение в Telegram-бот со ссылкой на пост.

### 3.2 Frontmatter

Схема контент-коллекции остается как есть. `pubDate` ОБЯЗАТЕЛЕН технически (сортировка, sitemap, dedup по времени) - но не отображается на сайте.

```yaml
---
title: "..."          # до 60 символов, без кликбейт-штампов
description: "..."    # 140-160 символов
pubDate: 2026-08-11   # служебное поле, в UI не выводится
tags: ["news", "..."] # первый тег всегда news
author: "AIBuilderHub"
draft: false
---
```

## 4. Мультиагентность: критики

Каждый критик - отдельный вызов LLM со своим системным промптом, возвращает строго JSON (`CritiqueReport`: verdict PASS/REVISE/REJECT, issues[], в issue - цитата и конкретное требование). Оркестратор гоняет цикл writer -> критики максимум 3 раза. Если после 3 итераций хоть один критик дает REJECT - пост не публикуется, тема помечается failed, день пропускается с алертом.

1. **Fact-checker**: каждое проверяемое утверждение должно опираться на переданные источники. Цифры, цены, названия моделей, даты релизов - только из источников. Никаких выдуманных бенчмарков и "по данным исследований". Неподтверждаемое -> вычеркнуть или смягчить до мнения.
2. **AI-pattern critic**: ловит машинные паттерны (полный список - banned_patterns.yaml, п. 6). Проверяет ритм: длина предложений должна плавать, абзацы неравномерные, есть короткие рубленые фразы.
3. **Editor/Value critic**: пост отвечает на вопрос "что это значит для соло-предпринимателя и что делать". Режет воду, требует конкретику. Проверяет, что это не пересказ пресс-релиза.
4. **SEO + integrity critic**: title/description по лимитам, slug без дат и мусора, 1-2 внутренние ссылки на существующие статьи сайта (список slug'ов подается в промпт), внешние ссылки на первоисточники живые (HEAD-запрос), нет упоминаний дат в теле ("today", "this week", "June 2026" - запрещены, текст должен быть вне времени).

## 5. Дедупликация (два уровня)

- **Уровень источника**: `published_topics.json` хранит все обработанные source_url и нормализованные заголовки. Кандидат с уже виденным URL отбрасывается на ingest.
- **Уровень смысла**: перед публикацией считается embedding заголовка+описания нового поста (Voyage AI или локально sentence-transformers в CI) и сравнивается косинусной близостью со всеми опубликованными. Порог: > 0.86 - дубль, REJECT. Дополнительно грубая проверка: пересечение 3-граммов заголовков > 40% - дубль. Плюс проверка коллизии slug по файловой системе.
- Reference-статьи (обзоры Cursor, Lovable и т.д.) в dedup-базу включаются тоже: новость "Cursor поднял цены" - ок, а "обзор Cursor" - дубль существующего.

## 6. Анти-AI язык (humanizer)

`banned_patterns.yaml` - жесткий блок-лист, проверяется регексами ДО и ПОСЛЕ LLM-прогона. Минимальный состав (расширяемый):

- Типографика: длинное тире (—) запрещено всегда, только дефис. Запрещены кавычки-елочки в EN-тексте, эмодзи, заголовки с Title Case Every Word.
- Слова-маркеры: delve, leverage (как глагол), moreover, furthermore, additionally, notably, arguably, seamless, robust, comprehensive, game-changer, revolutionize, landscape, realm, tapestry, unlock, unleash, elevate, embark, crucial, pivotal, foster, harness, in today's fast-paced world, at the end of the day, it's worth noting, let's dive in, in conclusion.
- Конструкции: "It's not just X, it's Y", "Whether you're A or B", тройные перечисления через запятую в каждом абзаце, абзацы-близнецы одинаковой длины, вопрос-и-сразу-ответ как прием чаще 1 раза на пост, буллеты там, где можно написать прозой.
- Структура: запрещены разделы "Introduction" и "Conclusion" как заголовки, пост не обязан иметь ровную структуру h2-h2-h2 с одинаковыми подпунктами.
- Требуемое: контрактации (it's, don't, you'll), редкие разговорные вставки, конкретные числа вместо "many/several", хотя бы одно субъективное суждение с обоснованием, первое лицо допустимо.

Существующие 23 статьи сайта использовать как эталон голоса: Claude Code при реализации должен извлечь из 3-4 лучших постов стилевую выжимку в voice.md (тон, длина абзацев, характерные обороты).

Честная оговорка: гарантии обхода AI-детекторов не существует и цели такой нет. Цель - текст, который не стыдно читать человеку.

## 8. Деплой и секреты

- Workflow `content-pipeline.yml`: cron `30 6 * * *` + `workflow_dispatch`. Шаги: checkout -> установить Python deps (с кешем) -> запустить пайплайн -> если создан новый .md: `npm ci && npm run build` (smoke-проверка, что Astro собирается с новым постом) -> commit+push -> деплой.
- Деплой: если сайт уже подключен к Cloudflare Pages через git-интеграцию - пуш в main достаточен. Если деплой ручной через wrangler - добавить шаг `wrangler pages deploy dist` в workflow. Claude Code должен проверить фактический способ по `.wrangler/` и настройкам и выбрать один путь.
- Секреты только в GitHub Actions Secrets: `ANTHROPIC_API_KEY`, при необходимости `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `VOYAGE_API_KEY`. В коде - только через pydantic-settings. Ни одного ключа в репозитории, `.env` в `.gitignore`.
- Concurrency group в workflow, чтобы два запуска не гонялись за git push.
- Бюджетный предохранитель: max_tokens лимиты на каждый вызов, не более 1 поста в сутки, счетчик вызовов LLM за прогон (жесткий потолок, например 25 вызовов) - защита от зацикливания критиков.

## 9. Аудит безопасности сайта

Разовая задача при реализации + автоматика в CI:

1. **Заголовки**: добавить `public/_headers` (Cloudflare Pages): Content-Security-Policy (без unsafe-inline насколько позволит Astro), X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: strict-origin-when-cross-origin, Permissions-Policy, HSTS.
2. **Секреты в истории**: прогнать gitleaks/trufflehog по всей git-истории репозитория. Найденное - ротировать.
3. **Зависимости**: `npm audit` + `pip-audit` как шаг CI (fail на high/critical). Dependabot включить.
4. **Workers**: проверить папку `workers/` - что там развернуто, нет ли захардкоженных ключей, открытых эндпоинтов без валидации входа.
5. **Cloudflare**: проверить, что включен Always Use HTTPS, TLS min 1.2, включить Bot Fight Mode.
6. **Поверхность атаки**: сайт статический - форм и БД нет, это главный плюс. Проверить, что в `dist/` не утекают исходники/конфиги (например .env, драфты). Убедиться, что `state/*.json` не содержит ничего чувствительного (не содержит - но проверить).
7. Отчет об аудите - отдельным файлом `SECURITY-AUDIT.md` с найденным и исправленным.

## 10. Наблюдаемость и отказоустойчивость

- structlog, JSON-логи в stdout (читаются в GitHub Actions).
- tenacity: 3 ретрая с экспоненциальной паузой на каждый внешний вызов (Anthropic, фиды, HN, Reddit).
- Любой сбой дня - это пропущенный день, не сломанный сайт: публикация атомарна (файл пишется только после PASS всех критиков), git push - последний шаг.
- Если workflow упал - GitHub сам шлет письмо владельцу репозитория. Этого достаточно для старта.

## 12. Критерии приемки

- Workflow отрабатывает по крону без участия человека; 1 новый пост в сутки появляется на aibuilderhub.app.
- Ни в одном месте UI не отображается дата.
- Повторный прогон в тот же день не создает дубль (dedup + concurrency).
- Ни один пост не содержит паттернов из banned_patterns.yaml (тест в CI).
- `npm audit`/`pip-audit` чистые на high/critical, security-заголовки видны в ответе сервера (проверить curl'ом).
- Все ключи только в GitHub Secrets, gitleaks по истории чист.
- Пост при ручной проверке: факты соответствуют источникам, есть ссылки на первоисточники, читается как написанный человеком.

## 13. Риски - прочитай, это важно

1. **Google и масс-AI-контент**: политика Google наказывает не AI как таковой, а scaled content abuse. 1 качественный пост в день - приемлемый темп, но если трафик не растет за 2-3 месяца - остановить и пересмотреть, а не наращивать объем.
2. **Копирайт**: пересказ фактов легален, копирование формулировок - нет. Поэтому в промпт writer'а идут только выжимки, и обязательны ссылки на первоисточники. Полнотекстовый скрейпинг чужих статей в пайплайн не встраивать.
3. **Reddit/HN API**: публичные JSON-эндпоинты Reddit без OAuth терпимы к 1 запросу в день, но могут закрутить гайки - клиент должен деградировать мягко (источник выпал - пайплайн жив).
4. **Стоимость**: ~30 постов/мес с критиками - ориентировочно $5-15/мес на Sonnet. Потолок вызовов (п. 8) обязателен.
5. **Галлюцинации**: fact-checker снижает, но не обнуляет риск. Постфактум-чтение владельцем - это и есть последний рубеж, не отключай его хотя бы первый месяц.
6. **"Виральность" != трафик сайту**: новостной контент живет 48 часов и почти не собирает SEO-трафик. Деньги сайту приносят evergreen-обзоры с афилками. Новости - это свежесть домена и повод для возврата читателей, не основная ставка. Не жертвовать evergreen-контентом ради конвейера.
